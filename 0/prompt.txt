<result>## Security Review — flowstate (Sources/MurmurKit, scripts)

**High — loopback port adoption trusts path, not owner (`Sources/MurmurKit/LoopbackSession.swift:56-67`).** `resolvePort` decides to "adopt" an existing listener on the whisper/llama/moshi port by checking only that the listening PID's resolved executable path matches the configured binary (`resolvedPath(path) == target`); it never checks the process's owning UID. Since 127.0.0.1 is shared by every local account on the Mac, and Homebrew binaries (`/opt/homebrew/bin/whisper-server` etc.) are normally world-executable, another local account can simply launch that same binary first to squat the port, and Murmur will "adopt" it as trusted, uploading the victim's microphone WAV to it and pasting back whatever text it returns via synthetic ⌘V into the victim's focused window. Fix: also require the listening PID's UID to equal `getuid()` before adopting, and fall back to `.spawn` on a private port otherwise (a shared-secret handshake, as already done for Kyutai, closes the same-user-malware variant too).

**Medium — whisper-server/llama-server have no auth token, unlike Kyutai (`Sources/MurmurKit/WhisperCppEngine.swift:139-154`, `Sources/MurmurKit/LlamaCppChatEngine.swift:160-186` vs. `scripts/install_kyutai.sh:57`, `KyutaiStreamingEngine.swift:131`).** Only the Kyutai path sends a per-install random `kyutai-api-key`; the whisper and llama requests carry no credential at all, so any other local process/account can call `/inference` or `/v1/chat/completions` directly (resource abuse, and it removes the one mitigation that would otherwise make the port-hijack above harder). Fix: pass `llama-server --api-key` (it supports it) plus a matching `Authorization` header, and bind whisper-server behind the same UID-bound check as above.

**Medium — plaintext dictation lingers longest on the pasteboard exactly when it's a secret (`Sources/MurmurKit/TextInserter.swift:37-46` vs. `:48-53`).** Under secure input (i.e., the user is dictating into a password field) the staged text is left on `NSPasteboard.general` in cleartext for `secureClearDelay` = 60s (`TextInserter.swift:24`), vs. 0.6s (`Config.swift:110`) in the normal paste path — so the one case that is provably sensitive is also the one exposed longest to any clipboard-history tool or clipboard-polling malware. Fix: shrink `secureClearDelay` drastically (a few seconds) or clear as soon as `changeCount` shows the user has manually pasted, rather than waiting a fixed 60s.

**Low — `~/.config/murmur` directory permissions aren't repaired by the auto-learn writer (`Sources/MurmurKit/AutoLearnStore.swift:111-119`).** `Config.save()` explicitly re-chmods a pre-existing directory to 0700 (`Config.swift:288-290`), but `AutoLearnStoreFile.save()` does not, so if that directory pre-dates the 0700 default (upgrade from an older build) and `autolearn.json` is the first thing written, the directory can stay 0755 — files inside stay 0600 (no content leak), but filenames/existence are listable by other local users. ## 3. Keeping sentences verbatim

- **Keep thinking off.** The DRES paper (arXiv 2509.20321) treats disfluency removal as "a deletion-only task". It found "reasoning models systematically over-delete fluent content".
- **VoiceInk's prompt** (`AIPrompts.swift`, commit eda5ccb) is a good model:
  - "Do not paraphrase, summarize, formalize, soften, strengthen, or change what the speaker intended."
  - "When uncertain, preserve the original wording."
  - It lists correction signal words ("wait", "actually", "scratch that", "I mean"), puts terms in a `&lt;CUSTOM_VOCABULARY&gt;` block, and gives 5 input/output examples.
  - Drop its paragraph and list rules, because they invite rewrites.
- **OpenWhispr's prompt** (`prompts.json`) says "\"Actually\" used for emphasis is not a correction". It gives the example "send it by thursday no wait friday period" → "Send it by Friday."
- **Prompting alone still loses words.** SpeakoFlow measured a spoken word dropped on 6.7% of transcripts for Qwen3.5 9B at temperature 0.
- **Add a guard.** In Swift, run `outWords.difference(from: inWords)` on lowercased words.
  - If the output inserts any word that is not in the transcript or the glossary, reject it and fall back to the raw transcript.
  - I found no dictation app that does this.
- **A per-request grammar** (llama-server's `grammar` field, GBNF) could allow only the transcript's words, in order, each optional, plus glossary terms. That makes paraphrasing impossible. I found no implementation, and the speed cost is unmeasured.
- **Edit operations:** the JSON Whisperer paper (arXiv 2510.04717) has the model return RFC 6902 patches instead of rewritten text. That used 31% fewer tokens than full rewrites.

## 4. llama-server (checked at build b10621)

- **Prompt caching is on by default.** `cache_prompt` defaults to `true`, so a byte-identical system prompt and glossary at the start is reused, and only the new part is processed. Check `timings.cache_n` in responses to confirm.
  - `--cache-reuse N` (default 0) only matters when a chunk in the middle of the prompt changes.
- **Hybrid models** (Qwen3.5, LFM2, Nemotron-H) reuse cached prefixes through checkpoints. The fix for prompts under 8192 tokens (#28302) merged 2026-09-08, after your build.
- **Flash attention:** `-fa on|off|auto`, default auto. The defaults `-b 2048 -ub 512` are already fine for short prompts.
- **Speculative decoding:**
  - With a draft model: `-md FILE --spec-draft-n-max N` (default 3).
  - Without one: `--spec-type ngram-simple`. The docs name rewriting as its use case.
  - `--spec-default` selects ngram-mod (n-match 24), which is meant for longer text.
- **Output cap:** `n_predict` defaults to -1 (unlimited). Cap it near 1.3 × input tokens + 32.
- **Thinking:** turn it off with `-rea off`.

   - Evidence: prompting alone dropped words on 6.7% of transcripts, and cleanup output mostly copies its input, which is what ngram drafting speeds up.
